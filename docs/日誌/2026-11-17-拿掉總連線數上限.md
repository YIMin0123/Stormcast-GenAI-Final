# 拿掉伺服器 256 條總連線上限

- 狀態：已提交（還沒上線）
- 日期：2026-11-17
- 作者：Claude Sonnet 5.5
- 提交：見 git log（標題「拿掉 256 條總連線上限」）
- 會動的檔案：server/index.js、docs/工程架構手冊.md

## 做了什麼
使用者要求拿掉 `server/index.js` 的 `MAX_CONNECTIONS = 256`（WebSocket 升級前 `wss.clients.size >= 256` 就回 503），不要讓它卡住同時在線人數。人數上限現在只看每房 30 人（`MAX_PLAYERS`）加房間自動增開。手冊那句同步改掉。

## 要知道的事
- 這是 Codex 在 `2026-11-17-正式機管理入口加固.md` 加的防護之一，其餘都還在：每個來源（IPv4 或 IPv6 /64）同時最多 16 條、每來源與全服的握手速率、新訪客速率、10 秒內沒 hello 就斷、Origin 檢查、Caddy 的標頭限額。
- **速率限額仍會擋住短時間大量湧入**：全服握手突發 256、每分鐘補 480；新訪客全服突發 48、每分鐘補 60（`server/admission.js` 的 `TOTAL_*`）。也就是說「一分鐘內新來的陌生人」超過約 60 個會被要求稍後再試，這跟「同時在線多少人」是兩回事。推廣湧入前要不要放寬，另外決定，這次沒動。
- 沒有總數上限後，同時在線人數的實際天花板是那台共用 GCP 機器（還跑著瓦爾海姆）的記憶體與 CPU，沒有實測過。
