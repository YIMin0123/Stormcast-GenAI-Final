# Stormcast（海嘯模擬器）AI 工程架構手冊

> **給 AI 的第一句話**：這是一份「活的現況地圖」。開工前先讀本檔快速定位模組與鐵律；當你的改動影響了模組職責、共用參數、座標結構、測試指令或核心規則時，**收尾前必須同步更新本文件（見文末〈文件動態維護協定〉）**。

---

## 1. 專案定位與世界現況

- **遊戲類型**：WebGL（Three.js）3D 線上多人航海釣魚與風暴生存遊戲（支援電腦與手機橫向觸控）。
- **核心迴圈**：母港領小舢舨出發 → 依水深／離岸距離／島礁釣場／魚群熱點／日夜風浪釣魚（蓄力拋竿＋張力區間收線，硬拉會爆竿）→ 躲避或挑戰海上事件（風暴、雷暴、颱風長湧、水龍捲、漩渦、淺水堆高捲浪的海嘯）→ 回母港或右下大港賣魚（實體魚標本登「本房紀錄」與「今日紀錄」看板）→ 買油、扳手修船、升級釣竿／引擎、買魚箱、換漁船與大漁船、災後撿漂流寶箱、爬大島高山與鑽透天藍洞探險。
- **世界空間（`2048 × 2048` 公尺，原點在正中央，`+x` 東、`+z` 南）**：
  - **左上潮汐灣（`home`）**（玩家看到的名字是「潮汐灣」；程式與文件裡的「母港／母島」都是指它）：木棧橋小漁村（新手出生點、商店買船買裝備、50kg 圓盤秤收購站、雙排行榜看板）。背對西北來浪，港內平靜。
  - **右下探險大港灣島（`haven`）**：馬蹄形巨崖海灣（灣口偏西避開直灌長浪）、丁字深水碼頭、依山小屋、大燈塔、吊鉤大秤批發收購站（收購價 `+15%`）、碼頭加油柱；島背有 65m 高山、湧泉小河與瀑布（踩入順流滑水）、天窗跳水台、透天洞穴（4.2m 寬海蝕暗門僅小舢舨與游泳可進）、山頂烽火台與古鐘。
  - **中央海域三處礁石（`reefs`）**：海蝕巨石拱門（`arch`，大船可穿過）、淺水環礁與沉船暗礁陣（`atoll`，水深 `-0.6m～-1.1m` 小舢舨可鑽、大船擱淺）、中途閃光燈標岩嶼（`beacon`）。正中央保留離大島 400m 以上的開闊遠洋區。
- **多人房間架構**：強制連線（WebSocket）。常駐房數由 `SERVER.fixedRooms` 決定（目前只開 1 號港；開更多時每間上限 30 人、遊戲時間各差 8 小時），全滿才開臨時房；臨時房人少自動合併回常駐房。玩家金錢、船隻、裝備、未賣漁獲依裝置 token 存於伺服器（`server/profiles.js`），依 `SERVER.refresh` 定時全服刷新（目前每 72 小時、台灣時間 05:00）。

## 2. 開發、預覽與實測速查

### 工作方式（多個 AI 共用一份）
- 只有一個資料夾 `C:\GAMER\海嘯模擬器`、一條 `main`：所有 AI 直接在 main 上改、本地提交，不開分支與工作副本（使用者當次指定才開，做完合回刪掉）。推 main＝發佈，等使用者說。
- 提交前 `git diff --cached --name-status` 確認只有自己的檔案；別人未提交的改動不要動、不要一起提交。
- 伺服器全專案只有下面這一組（`.claude/launch.json` 的 `web`、`server`）；已在跑就沿用，不另開其他埠。Vite 熱更新，誰改了什麼同一頁馬上看得到。

### 啟動服務
| 用途 | 指令 | 預設埠號 | 說明 |
|---|---|---|---|
| 前端開發伺服器（`web`） | `npm run dev` | `http://localhost:5173` | Vite，開發模式下預設自動連 `ws://localhost:8787` |
| 多人開發伺服器（`server`） | `node server/dev.js` | `ws://127.0.0.1:8787` | 開啟 `STORMCAST_DEV=1`（啟用開發者模式與測試指令），存檔隔離在 `server/data/dev/` |
| 正式版打包檢查 | `npm run build` | — | 檢查語法與打包是否通過（ES2022 target） |
| 碰撞回歸測試 | `node --test tools/collision.test.js` | — | 檢查商店入口、水下碰撞、高速移動、大港小屋平台與下落慣性 |

### 常用網址參數與預覽頁（實測必備）
| 網址 / 參數 | 效果與用途 |
|---|---|
| `/?test` | **AI 實測必加**：改用 `sessionStorage` 隔離玩家身分與存檔，每個分頁都是獨立新玩家，不動使用者正在玩的正式分頁與存檔 |
| `/?fps`、`/?diag` | 顯示 FPS、解析度、GPU 資訊與詳細渲染診斷數據 |
| `/?touch`、`/?notouch` | 在電腦強制開啟手機觸控 UI ／ 在觸控筆裝置強制關閉手機 UI |
| `/?boy` | 切換男版人物外觀（預設女版） |
| `/?server=ws://...` | 指定連線的伺服器位址 |
| 按 `B` | 輪流換餌（手機是右上角的鉤子按鈕）；餌在商店東半邊後牆的工作台買，每拋一次竿用掉一個 |
| `/sample.html?scene=harbor` | 低面樣品間：單獨預覽母港島（可調色板、時段、陰影、海面模式，檢查 draw calls） |
| `/sample.html?scene=haven` | 低面樣品間：單獨預覽右下探險大港灣島（含預設多角度鏡頭按鈕） |
| `/sample.html?scene=reefs` | 低面樣品間：單獨預覽海上三組礁石群（石拱門、沉船環礁、燈標） |
| `/figure.html` | 單獨預覽人物骨架、動作與表情貼圖 |

### 開發者飛行模式（僅連上 `server/dev.js` 時生效，參數在 `DEVMODE`）
- **連按兩下空白鍵**：切換飛行模式（飛行時不會累、不會溺水；飛過地面高度 `+ wallTop` 可直接越過房屋與圍牆）。
- **移動控制**：`WASD` 水平飛行（24 m/s）、按住 `R` 衝刺（72 m/s）、`Shift` 上升、`Q` 下降（勿用 `Ctrl+W` 以免關閉分頁）。
- **設定面板測試鈕**：開發環境下設定面板內可直接觸發海上事件、快轉時間與加錢。

## 4. 核心工程鐵律與踩坑紀錄（必讀 Gotchas）

1. **禁止寫死世界座標與朝向**：
   - 想新增或移動島嶼、港口、礁石，參數一律放 `src/config.js`，透過 `src/frame.js` 的 `makeFrame()` 轉成各自的設計圖座標。幾何建模與矩形碰撞在局部座標寫，擺進場景用 `placeInFrame()`。
2. **海床高度圖 `bed` 與 `main` 必須分開（`src/terrain.js`）**：
   - `bed` 包含母島＋大港灣島＋海上礁石（給船隻擱淺、岸邊碎浪白沫、停船水深檢查用）。
   - `main` **只含母島與大港灣島，不含海上礁石**（專門給 `computeDanger` 與 `computeOffshore` 用）。若把海中央礁石混進 `main`，礁石周圍幾百公尺會被當成近岸，導致外海風暴消失、鮪魚與旗魚釣不到。
3. **地面碰撞必須踩在「實際畫出的三角面」上**：
   - 低面地形一格 1～2.7 公尺且有岩層階梯變形，跟平滑算式 `homeBed` / `havenHeight` 會差幾十公分。人物走路與種樹種草一律查 `islandTerrain` 回傳的 `ground.at(x, z)`（`HOME_LAND.at` / `HAVEN_LAND.at`），腳才不會陷地或浮空。
4. **雙層空間與窄水道碰撞（大港透天洞穴）**：
   - 走路查 `landAt` 時透過 `havenDeck`（跳水台、碼頭棧板）與 `caveUnder(vx, vz, walker.feet)` 區分上下層：人在洞頂高度踩山坡，跳進天窗或從暗門進洞則踩下層深潭與岩台。
   - 暗門水道僅 4.2m 寬，全域 2m 一格的海床圖太粗，因此在 `nearCave` 範圍內船隻碰撞（`boatGround`）改查精確算式 `havenLow`，並以 `caveGate` 擋住過寬的大船。
5. **鏡頭防穿牆禁止對高面數模型打射線**：
   - 建築與燈塔一律註冊隱形的簡單方塊 `camBoxes`（`camProxy`），透天洞穴岩壁則查數學距離場 `caveRock(x, y, z)`，避免手機每幀 raycast 十幾萬個三角形掉幀。
6. **母港島的亂數種子順序保護（`harbor3d.js`）**：
   - 母港共用 `rng(7919)`，為了不讓新增的商店／小屋細節改變後面海岸大石頭與樹木的既有位置，獨立子模組（`shopMarket.js`、`houses.js`）使用各自的亂數種子，並在 `harbor3d.js` 保留固定次數的 `r()` 跳過。改動母港子模組時請維持此隔離做法。
7. **GLSL 螢幕導數陷阱（`surfaceDetail.js` 等著色器）**：
   - 在 D3D / NVIDIA（ANGLE）環境下，`dFdx`、`dFdy`、`fwidth` 與一般 `texture2D` 的隱式導數**嚴禁放在像素級別不一致的 `if` 分支內**，否則會產生 `NaN` 被泛光糊成整片閃黑。導數必須在分支外先算好，分支內取樣改用 `textureGrad`，且 `normalize` 前必檢查向量長度非零。
8. **手機效能適配鐵律（嚴禁自動壓解析度）**：
   - 像素比與解析度由使用者在設定決定，程式**不准偷降解析度**。
   - 任何新場景與新特效必須做**電腦／手機分檔（`TOUCH` 與畫質低中高）**：手機版地形格距加大（三角形減半）、省略 `fd` 細小裝飾、關閉 `tagSurfaces` 與 `surfaceDetail`、減少樹木／岩塊／藤蔓實例數、小河動態頂點色隔幀更新、貴的光影特效只開在電腦版。
9. **岸邊的浪跟著風向（`renderShaders.js` 的 `shoreFace`、`shoreTilt`，參數 `SHORE_WIND`）**：
   - 岸浪大小乘上「這段岸面迎不迎風」（離岸距離圖的梯度＝往海那一面，跟風吹來的方向比），背風面只剩 `lee` 成；相位加上順風斜推項，參考點跟著鏡頭走、`uShoreP` 累積補償，浪才不會跳。新增任何用 `shorePhase`／`shoreExpo` 的地方都要一起乘上、加上。
   - 地形著色器不准讀 `uShore`（會超過手機 16 個貼圖單元），迎風判斷改用地形自己的法線 `vN.xz`。
10. **部署同步提醒**：
   - 只改純前端畫面檔推發佈分支即可；一旦改到 `server/` 或 **3-A 列出的雙端共用檔**，上線時必須同步更新雲端伺服器（重啟服務會踢除房內連線），動伺服器或推 `main` 前務必先由使用者指示。
10. **介面顏色不寫死**：DOM 介面一律用 `index.html` `:root` 的 CSS 變數（JS 改顏色也寫 `'var(--sea)'`）；SVG／Canvas 畫的介面（表情輪盤、名牌、地圖標籤）照同一組色值。手機提示裡的按鈕名稱用 `touchSet()` 換成圖示，「互動」畫的是按鈕當下的圖示，所以 `updatePrompt` 要先 `touch.update` 再設提示。
10. **碰撞形狀與角色寬度**：
   - 母島岩石高度圖的原點與格距要對齊，形狀本身不額外膨脹；角色寬度由移動探測處理。水下查詢不能把棧板上的物件當成水下的牆，高速移動須分段檢查路徑。
   - 大港小屋石砌地基與門前平台的範圍、高度跟隨模型及實際地形，燈塔與燈標的底座、塔身分開計算。
11. **人物下落與河水**：離地或跳起時保留當下水平移動及河水速度；空中只能逐漸調整方向，撞牆消除受阻分量，落地清除空中速度。河水只推動接觸河床的人，離開瀑布後由慣性接手，避免重複施力或離開判定範圍時突然停住。
12. **船與棧橋的上下層**：人從船跳到橋時，依腳的高度選橋面或橋底；船和橋重疊時，腳高於橋面就選橋面。空中更換支撐面須維持原本的世界高度。船與棧橋間跨步的額外補位不能算進離地速度，否則人物會被彈飛。
13. **船上碰撞**：甲板範圍與船殼模型共用分段和寬度，艙蓋提供可踩的頂面。船舷按模型高度阻擋走路；足夠高的跳躍及走向附近碼頭仍可離船。
14. **天上的雲全部是手繪平塗風（`clouds.js` 烘焙、`renderShaders.js` 的 `paintTap`／`paintShade`／低雲層、參數 `CLOUDS`）**：
   - 晴天的積雲：載入時烘一張立方體環景圖（RGB 表面方向、A 有沒有雲），雲是一堆球疊成的，雲底大致是平的、高度微微起伏；會飄到頭頂的雲（`deep`）底下是幾顆大球圍成一團。天色一沉積雲轉成風暴灰。
   - 變天時的雲是著色器直接畫的**一整片低雲層**（高 `stormH`）：天色越沉從零星幾條長成整片，平塗三階、順著風拉長，暴風時底下再飄碎雲。它不用貼圖，所以天空、電腦海面倒影、手機倒影都一樣；沒有積雲圖的材質（手機倒影、`?nopaint`）晴天也留幾條，並保留三階平塗的地平線積雨雲。**不要再用一顆顆球去堆頭頂的風暴雲**（從底下看是一坨一坨的）。
   - 雲固定在世界座標、順風飄：積雲當成高 `H` 公里的平面做位移，`uPaintOff`＝鏡頭位置－飄移量；越靠近地平線的雲（仰角在 `nearLo`～`nearHi` 以下）越不跟著移，才不會把遠方的大積雨雲拉歪。A、B 兩組位移，A 飄出 `loop/2` 就由 B 從上風處接手，交疊 `morph` 公里，天空一塊一塊輪流換過去。低雲層用 `uDeck` 一路累加、不用換組。
   - 雲影：`main.js` 的 `driftClouds` 每幀從佈局（`cloudCores`）算出每朵積雲投在地上的位置，取最近 `shadowN` 朵傳 `uCloudSh`，與天上畫出來的對得上；變天時整體再照 `uGloom` 變暗。低面模型（母島、港口）原本就沒有雲影。改佈局、平面高度或位移公式時，`paintDir` 與 `driftClouds` 要一起改。
15. **魚大家共用（`server/room.js` 的 `loose`，參數 `SHARE`）**：
   - 自己的魚放在地上、甲板上、籃子裡（`fish.js` 的 `_pub` → `put`），伺服器記進 `room.loose`，同房的人都看得到；拿回手上、放進自己魚箱就 `take` 收回。誰先 `grab` 到算誰的（伺服器把那條從原主人的 `p.fish` 搬到撿的人名下）。魚箱裡的、手上的不在 `loose`，別人拿不到。
   - 母島籃子是共用的：按鈕送 `sell`（不帶清單），伺服器把籃子裡全部賣掉、每條的錢付給牠現在的主人。紀錄：價值 ≥ `SHARE.credit` 算釣到的人（`f.by`），其他算賣的人。
   - 地上、籃子裡放超過 `SHARE.life` 秒就消失（甲板上的不算）；主人斷線太久被收走時，他的魚留著變成沒主人。放在外面的魚不存進存檔、不在斷線接回的 `resume.fish` 裡，接回時照 `snapshot.loose` 放回原位；合併房間時一起搬過去。
   - 別人的魚只在本機畫（`remote`），不跳不滑；位置以主人那邊為準，他那邊跳一下、換地方會再送一次 `put`。
16. **魚箱與送東西（`server/fishBoxes.js`，參數 `FISHBOX`，算式 `src/boxdata.js`）**：
   - 箱子是伺服器的物件 `room.boxes`（`{bid, owner, fish:[uid], k, x, y, z, yaw, b}`；`k`＝`hand` 抱著／`d` 甲板（`b` 是哪個人的船、座標是船的局部座標）／`g` 地上／`w` 海上），改了就廣播 `{t:'box', add/del}`。箱裡的魚還在主人的 `p.fish`，但不在 `loose`、不存進頂層存檔，別人拿不到。
   - 只有一種箱子，每人最多 `FISHBOX.max` 個；滿了再買，伺服器回 `boxFull`，玩家答應後帶 `replace:true` 再買，最舊的那個連魚一起清掉。買了直接抱在手上；只有主人抱得動，抱著走路照箱裡重量變慢（`player.load`），不能游泳、爬梯（下水就自動放在海上浮著）。
   - 放魚不限條數、照模型體積：`boxFit` 看太長（`BOX_LONGEST`）或滿了。魚放進別人的箱子＝送給箱主（`boxIn`）。抱著箱子對準籃子／大港吊鉤按 E 整箱賣（`sell` 帶 `bid`），箱子留在手上。
   - 送魚、送箱（`give` → 對方收到 `offer` 跳卡片 → `giveAns`）：`FISHBOX.offerSec` 秒沒回答算拒絕；送箱連裡面的魚一起，對方已經有 2 個箱子就送不了。
   - 存檔：箱子跟著主人存（`savedBoxesOf`／`loadBoxes`），斷線太久收起來、下次進來 `homeBoxes` 放回自己船的甲板上；舊存檔的 `boxLv` 換成一個箱子。船沉了甲板上的箱子浮起來（`floatBoxes`），魚還在。

## 5. 文件動態維護協定（AI 必執行）

為了防止工程文件腐化過時，任何 AI 在完成程式碼修改準備收尾時，請逐項核對以下清單；**只要命中任一項，請在同一個任務內直接更新本文件（與相關規則檔）**：

1. **新增、刪除或合併檔案／模組** → 更新〈3. 目錄與模組地圖〉，特別標明是否屬於「雙端共用（禁碰 Three.js / DOM）」。
2. **修改世界配置、新增島嶼／港口／釣場或改動座標架構** → 同步更新本檔〈1. 專案定位與世界現況〉與 `docs/座標與地圖規則.md`。
3. **新增或修改網址測試參數、啟動指令、開發者快捷鍵** → 更新〈2. 開發、預覽與實測速查〉。
4. **踩到新的跨平台／效能／渲染／物理大坑並修好** → 濃縮成 2～3 行規則補進〈4. 核心工程鐵律與踩坑紀錄〉。

### 維護撰寫原則
- **只寫「現在程式碼長怎樣」，不寫歷史流水帳**：舊設定被取代就直接改寫或刪掉，不要留「以前是 X、某月某日改成 Y」（歷史交給 `git log`）。
- **保持精煉可掃讀**：優先使用表格與條列，整份手冊控制在 250 行以內，確保後續 AI 一次 `Read` 就能完整讀入且不浪費上下文空間。
