# Stormcast（海嘯模擬器）AI 工程架構手冊

> **給 AI 的第一句話**：這是一份「活的現況地圖」。開工前先讀本檔快速定位模組與鐵律；當你的改動影響了模組職責、共用參數、座標結構、測試指令或核心規則時，**收尾前必須同步更新本文件（見文末〈文件動態維護協定〉）**。

---

## 1. 專案定位與世界現況

- **遊戲類型**：WebGL（Three.js）3D 線上多人航海釣魚與風暴生存遊戲（支援電腦與手機橫向觸控）。
- **核心迴圈**：母港領小舢舨出發 → 依水深／離岸距離／島礁釣場／魚群熱點／日夜風浪釣魚（蓄力拋竿＋張力區間收線，硬拉會爆竿）→ 躲避或挑戰海上事件（風暴、雷暴、颱風長湧、水龍捲、漩渦、淺水堆高捲浪的海嘯）→ 回母港或右下大港賣魚（實體魚標本登「本房紀錄」與「今日紀錄」看板）→ 買油桶、開進修船屋或大港船塢付錢修船、升級釣竿／引擎、買魚箱、換漁船與大漁船（在平板上換、叫船）、組船隊、捐款衝週榜稱號、災後撿漂流寶箱、爬大島高山與鑽透天藍洞探險。
- **世界空間（`2048 × 2048` 公尺，原點在正中央，`+x` 東、`+z` 南）**：
  - **左上潮汐灣（`home`）**（玩家看到的名字是「潮汐灣」；程式與文件裡的「母港／母島」都是指它）：木棧橋小漁村（新手出生點、漁具行只賣釣具／餌／誘魚桶／魚箱／油桶、50kg 圓盤秤收購站、三塊排行榜看板、漁會捐款箱與意見信箱；船務不在這裡辦）。背對西北來浪，港內平靜。
  - **右下探險大港灣島（`haven`）**：馬蹄形巨崖海灣（灣口偏西避開直灌長浪）、丁字深水碼頭、依山小屋、大燈塔、吊鉤大秤批發收購站（收購價 `+15%`）、補給所＋船塢分店（修船台、買船、引擎、改裝、塗裝）、榮譽榜亭（第二組看板、捐款箱、意見信箱）、東岸高台海神祭壇；島背有 65m 高山、湧泉小河與瀑布（踩入順流滑水）、天窗跳水台、透天洞穴（4.2m 寬海蝕暗門僅小舢舨與游泳可進）。
  - **母港東南外海的海上修船屋（`seaYard`）**：固定樁平台＋U 形船塢（修船台、買船、引擎、聲納、集魚燈、塗裝、油桶），半徑 `WORLD.seaYard.calmR` 內浪高打折（`terrain.js` 的 `CALM_ZONES`），海嘯照樣通過。
  - **中央海域三處礁石（`reefs`）**：海蝕巨石拱門（`arch`，大船可穿過）、淺水環礁與沉船暗礁陣（`atoll`，水深 `-0.6m～-1.1m` 小舢舨可鑽、大船擱淺）、中途閃光燈標岩嶼（`beacon`）。正中央保留離大島 400m 以上的開闊遠洋區。
- **多人房間架構**：強制連線（WebSocket）。常駐房數由 `SERVER.fixedRooms` 決定（目前只開 1 號港；開更多時每間上限 30 人、遊戲時間各差 8 小時），全滿才開臨時房；臨時房人少自動合併回常駐房。玩家金錢、船隻、裝備、未賣漁獲、魚箱依裝置 token 存於伺服器（`server/profiles.js`），依 `SERVER.refresh` 定時全服刷新（目前每 72 小時、台灣時間 05:00）。圖鑑另外存（`server/dex.js` 的 `Dexbooks`，`dexbook.json`），刷新不清。

## 2. 開發、預覽與實測速查

### 工作方式（多個 AI 共用一份）
- 只有一個資料夾 `C:\GAMER\海嘯模擬器`、一條 `main`：所有 AI 直接在 main 上改、本地提交，不開分支與工作副本（使用者當次指定才開，做完合回刪掉）。上線用 `bash deploy/push.sh`（見下方「上線與部署」），等使用者說；推 GitHub 不會發佈。
- 提交前 `git diff --cached --name-status` 確認只有自己的檔案；別人未提交的改動不要動、不要一起提交。
- 伺服器全專案只有下面這一組（`.claude/launch.json` 的 `web`、`server`）；已在跑就沿用，不另開其他埠。Vite 熱更新，誰改了什麼同一頁馬上看得到。

### 上線與部署（不經過 GitHub）
- 網頁和遊戲伺服器都在 GCP `valheim-tw`（`asia-east1-b`），同一個網址 `https://35-229-248-193.sslip.io/`：Caddy 把 WebSocket 轉給 Node 伺服器（`stormcast` 服務、埠 8787），其他路徑直接送 `/var/www/stormcast` 裡打包好的網頁。設定檔在 `deploy/`（`Caddyfile`、`stormcast.service`）。
- 上線：在專案資料夾跑 `bash deploy/push.sh`（網頁＋伺服器，伺服器會重開、房裡的人斷線重連）、`bash deploy/push.sh web`（只換網頁）、`bash deploy/push.sh all <git 版本>`（指定版本）。它用 `git archive` 取出**已提交**的版本、在本機打包、用 `gcloud` 傳上去，沒提交的改動不會被帶上去。只改畫面可用 `web`；改到 `server/` 或兩邊共用的檔（`src/fishdata.js`、`boatdata.js`、`layout.js`、`terrain.js`、`weather.js`、`config.js` 等）要用完整的。
- GitHub 倉庫是私人的、只當備份；舊的 GitHub Pages 發佈已拿掉（`.github/workflows/pages.yml` 已刪）。倉庫私有後，GCP 不能再 `git pull`，所以才用上傳的方式。
- 換網域：改 `deploy/Caddyfile` 第一行、`stormcast.service` 的 `ORIGINS`、`src/net.js` 的 `PROD_SERVER`，再重新上線。伺服器上的舊版會留在 `/opt/stormcast.old`、`/var/www/stormcast.old`，出事可以換回來（下次更新時才刪）。

### 玩家活動統計（管理網頁，`server/activity.js`、`statsPage.js`）
- 看：`bash deploy/stats.sh`（用 ssh 從伺服器抓 `/admin/stats` 存成檔案並開啟；`stats.sh json` 印原始資料）。本機開發版直接開 `http://localhost:8787/admin/stats`。頁面是自給自足的單一 HTML，離線能開，要更新就再抓一次。
- 內容：現在線上、每日統計（不同玩家、電腦／手機、新玩家、場次、平均時長、同時最高、釣到、賺花）；點一天看每小時最高人數與時間表（進房、斷線、接回、離開、換名）；玩家清單（名字沿革、IP、裝置、累計、同 IP 的其他代碼）。
- 存取：`/admin/stats`、`/admin/stats.json` 只收本機的 GET（連線來自 loopback、沒有 `X-Forwarded-For`、`Host` 是本機、沒有 `Origin`、`Sec-Fetch-Site` 只許 none／same-origin），Caddy 另把 `/admin*` 對外擋成 404。沒有帳號密碼，所以這兩層都不能拿掉。
- 資料：`DATA_DIR/activity/`（正式機 `/var/lib/stormcast/activity/`）每天一個 `YYYY-MM-DD.jsonl`（台灣時間）加 `people.json`，保留 30 天（`KEEP_DAYS`），不進 git；紀錄只放認人代碼的雜湊（`pid`），因為代碼本身能接回別人的進度。
- **只記正式機**：測試伺服器（`node server/dev.js`，`DEV`）建 `Activity` 時 `off: true`，不寫任何紀錄；本機 `http://localhost:8787/admin/stats`（與 `.json`）改由 `server/prodStats.js` 透過 `gcloud compute ssh --tunnel-through-iap` 向正式機的 `/admin/stats.json` 要資料再畫出來（20 秒快取、逾時 45 秒；要這台電腦的 gcloud 已登入，失敗回 502 並提示）。所以本機這頁看到的就是上線版玩家；`bash deploy/stats.sh` 也能用。
- IP 只在連線來自本機（Caddy）時才採 `X-Forwarded-For`（`clientIp`）；電腦／手機看 User-Agent。遊玩摘要在進房、離開各拍一張快照比較，賺花用 `hub.keep`（約 10 秒）取樣；`room.js` 只在 `remove()` 呼叫 `hub.activity?.end`。改這塊跑 `node --test tools/activity.test.js`。

### 正式機管理入口與檔案權限
- Stormcast 和 Valheim 所在 VM 的 TCP 22 只允許 IAP 轉送，直連 22、3389 被 GCP 防火牆拒絕。部署、公告、統計及手動 `gcloud compute ssh`／`scp` 要帶 `--tunnel-through-iap`。
- 正式程式由 root 擁有，systemd 使用 `stormcast` 服務帳號、唯讀系統與獨立暫存區。`/var/lib/stormcast` 為 700，存檔為 600，建立新檔時使用 `UMask=0077`。

### 連線入口與訪客限額
- Caddy 對外封鎖 `/admin` 與子路徑，只把 `/` 的 WebSocket 握手轉給 Node。`/status` 只轉發一般 HTTP。讀取 HTTP 標頭最多等 5 秒、標頭上限 16 KB。正式瀏覽器頁面的 `connect-src` 只許本站、`blob:`／`data:` 與官方 WebSocket（`blob:` 不能拿掉：人物模型 glb 內嵌的貼圖是 GLTFLoader 用 blob 網址 fetch 的，擋掉人物會變全白）。正式 Node 也只接受 `/` 的 WebSocket 握手、驗證 `Origin`，在升級前只做來源與速率限額（**沒有總連線數上限**：人數上限只看每房 30 人、房間自動增開，不會被連線數卡住）。任何連線若 10 秒內沒有有效 `hello` 就斷開。
- 正式服依 Caddy 傳來的 IPv4 或 IPv6 `/64` 分組。每組可同時連 16 條。握手突發可用 24 次，每分鐘補 120 次。建立訪客突發可用 8 次，每分鐘補 12 次，既有玩家的進房與重連不扣訪客額度。全服握手突發 256 次，每分鐘補 480 次。新訪客全服突發 48 次，每分鐘補 60 次。這些速率限額只在非開發模式生效。測試用 `node --test tools/admission.test.js`。

### 開發者飛行模式（僅連上 `server/dev.js` 時生效，參數在 `DEVMODE`）
- **連按兩下空白鍵**：切換飛行模式（飛行時不會累、不會溺水；飛過地面高度 `+ wallTop` 可直接越過房屋與圍牆）。
- **移動控制**：`WASD` 水平飛行（24 m/s）、按住 `R` 衝刺（72 m/s）、`Shift` 上升、`Q` 下降（勿用 `Ctrl+W` 以免關閉分頁）。
- **設定面板測試鈕**：開發環境下設定面板內可直接觸發海上事件、快轉時間與加錢。

## 3. 目錄與模組地圖

### A. 雙端共用純資料與算式層（瀏覽器 ＋ Node 伺服器共用）
> **鐵律**：以下檔案會被 `server/` 直接 `import`，**絕對不可引入 `three`、不可存取 `window` / `document` 等瀏覽器 API**！

| 檔案 | 職責 |
|---|---|
| `src/config.js` | 全世界唯一可調參數中心：地圖大小、母島／大港灣島／三處礁石的位置與朝向、浪向偏角、投擲參數 `THROW`、魚大家共用 `SHARE`、魚箱 `FISHBOX`、平板 `TABLET`（叫船範圍、冷卻、船指標距離與叫船後標幾秒、外海的距離、拿起平板的動畫秒數）、岸浪跟風向 `SHORE_WIND`、天上的雲 `CLOUDS`、開發者模式 `DEVMODE`、伺服器刷新設定 `SERVER` |
| `src/frame.js` | 座標轉換核心：`makeFrame()` 產生各島與礁石的局部設計圖座標 ↔ 世界座標轉換（`toWorld`/`toLocal`、`havenToWorld`/`havenToLocal`、`REEF_FRAMES`） |
| `src/terrain.js` | 生成全域海床高度圖 `makeTerrain()`（回傳含礁石的 `bed` 與僅含雙大島的 `main`）、避浪遮蔽圖 `computeShelter()`、離岸距離圖 `computeShoreDist()` |
| `src/weather.js` | 時間、潮汐、風速浪高公式、海嘯（`TSU`）與破浪捲舌（`CURL`）參數、長浪（`SWELL`，2048 秒循環確保全房浪況一致）、危險度與離岸距離計算、風暴前後的釣魚狀態 `Sea.fishStorm`（`before` 醞釀中／`after` 剛過去 `SEA_AFTER` 秒） |
| `src/layout.js` | 母港的互動與碰撞版面：棧板判定 `onDeck`、爬梯 `ladderY`、32 格停船位 `BERTHS`、商店商品架 `SHELF`、賣魚籃與看板座標 |
| `src/places.js` | 地名：`placeOfSpot`（釣魚點 → 「石拱門」「潮汐灣附近」「外海」，圖鑑記在哪釣到）、`placeAt`（任意一點，平板寫人、船、箱子在哪） |
| `src/tabletData.js` | 平板上的文字算式：方位 `dirName`／`whereFrom`、蒲福風級、天空 `skyOf`、潮汐 `tideText`、今天的預報 `forecast`、海上的徵兆 `signsOf`（純計算，不碰畫面；伺服器目前沒用到） |
| `src/boatdata.js` | 家當 `newKit()`（含餌庫存 `baits`、掛的餌 `bait`）、餌的商品 `bait_*`、三種船隻規格（`skiff` 小舢舨、`fisher` 漁船、`trawler` 大漁船）、商店價格與升級邏輯 `shopItem()` |
| `src/boxdata.js` | 魚箱的體積算式：每條魚佔多少體積 `fishVolume`、放不放得進 `boxFit`（太長／滿了）、抱著箱子走多快 `boxSpeed` |
| `src/fishdata.js` | 資料驅動的魚種表 `SPECIES`（36 種魚＋10 種雜物 `kind:'junk'`）：每種自帶稀有度 `rarity`（普通／少見／稀有）與出現條件 `spots`（水域 `where`、水深、離岸、日夜、清晨黃昏、雨、風暴前後）。`rollCatch()` 先擲雜物（`JUNK`）再依 `spots` 權重擲魚；餌 `BAITS`（蝦／小魚／花枝／特級亮片，越貴越容易釣到少見與稀有魚）；調分布只改這張表 |
| `src/announce.js` | 主頁公告文字 `NOTICE`（改公告只改這裡）與「距離下次全服刷新」倒數算法（由 `SERVER.refresh` 推算） |
| `src/fishzone.js` | 特殊釣場判定 `fishZone(x, z)`（`'river'` 高山小河、`'cave'` 透天洞穴、`'arch'`/`'atoll'`/`'beacon'` 三處礁石）與山上河面高度 `riverLevel()` |
| `src/extrasPlan.js` | 魚群熱點 `HOTSPOT`、災後漂流寶箱刷新點 `CHESTS`（含世界座標版） |
| `src/lowpoly/*Plan.js` | 純數字設計圖：`harborPlan.js`（母港）、`havenPlan.js`（大港灣島：山脊、透天洞穴、小河、跳水台、碼頭山城）、`reefPlan.js`（三組礁石） |
| `src/lowpoly/*Shape.js` | 純算式形狀：`homeShape.js`（母島海床與棧板）、`havenShape.js`（馬蹄山脊、洞穴 SDF `cavitySdf` 與雙層碰撞 `caveUnder`、小河曲線與滑水、大港棧橋與屋牆）、`reefShape.js`（三組礁石海床） |

### B. 低面平塗 3D 建模管線（`src/lowpoly/`，僅瀏覽器端）

## 4. 核心工程鐵律與踩坑紀錄（必讀 Gotchas）

1. **禁止寫死世界座標與朝向**：
   - 想新增或移動島嶼、港口、礁石，參數一律放 `src/config.js`，透過 `src/frame.js` 的 `makeFrame()` 轉成各自的設計圖座標。幾何建模與矩形碰撞在局部座標寫，擺進場景用 `placeInFrame()`。
2. **海床高度圖 `bed` 與 `main` 必須分開（`src/terrain.js`）**：
   - `bed` 包含母島＋大港灣島＋海上礁石（給船隻擱淺、岸邊碎浪白沫、停船水深檢查用）。
   - `main` **只含母島與大港灣島，不含海上礁石**（專門給 `computeDanger` 與 `computeOffshore` 用）。若把海中央礁石混進 `main`，礁石周圍幾百公尺會被當成近岸，導致外海風暴消失、鮪魚與旗魚釣不到。
3. **地面碰撞必須踩在「實際畫出的三角面」上**：
   - 低面地形一格 1～2.7 公尺且有岩層階梯變形，跟平滑算式 `homeBed` / `havenHeight` 會差幾十公分。人物走路與種樹種草一律查 `islandTerrain` 回傳的 `ground.at(x, z)`（`HOME_LAND.at` / `HAVEN_LAND.at`），腳才不會陷地或浮空。
4. **雙層空間與窄水道碰撞（大港透天洞穴）**：
   - 走路查 `landAt` 時透過 `havenDeck`（跳水台、碼頭棧板）與 `caveUnder(vx, vz, walker.feet)` 區分上下層：人在洞頂高度踩山坡，跳進天窗或從暗門進洞則踩下層深潭與岩台。
   - 暗門水道僅 4.2m 寬，全域 2m 一格的海床圖太粗，因此在 `nearCave` 範圍內船隻碰撞（`boatGround`）改查精確算式 `havenLow`，並以 `caveGate` 擋住過寬的大船。
5. **鏡頭防穿牆禁止對高面數模型打射線**：
   - 建築與燈塔一律註冊隱形的簡單方塊 `camBoxes`（`camProxy`），透天洞穴岩壁則查數學距離場 `caveRock(x, y, z)`，避免手機每幀 raycast 十幾萬個三角形掉幀。
   - 鏡頭防穿牆探測從固定的角色頭部高度起算。鏡頭被擠近時額外抬高注視點，避免探測起點跟著上幀的鏡頭距離變動。
6. **母港島的亂數種子順序保護（`harbor3d.js`）**：
   - 母港共用 `rng(7919)`，為了不讓新增的商店／小屋細節改變後面海岸大石頭與樹木的既有位置，獨立子模組（`shopMarket.js`、`houses.js`）使用各自的亂數種子，並在 `harbor3d.js` 保留固定次數的 `r()` 跳過。改動母港子模組時請維持此隔離做法。
7. **GLSL 螢幕導數陷阱（`surfaceDetail.js` 等著色器）**：
   - 在 D3D / NVIDIA（ANGLE）環境下，`dFdx`、`dFdy`、`fwidth` 與一般 `texture2D` 的隱式導數**嚴禁放在像素級別不一致的 `if` 分支內**，否則會產生 `NaN` 被泛光糊成整片閃黑。導數必須在分支外先算好，分支內取樣改用 `textureGrad`，且 `normalize` 前必檢查向量長度非零。
   - 雨絲著色器用常數索引讀取兩塊屋頂資料。S22+ 的 Adreno 730 搭配 ANGLE 時，迴圈索引版本在兩個階段編譯成功後仍會連結失敗。
8. **手機效能適配鐵律（嚴禁自動壓解析度）**：
   - 手機未設定解析度時使用 1.6×，可手動選 1.0× 至 2.0×。舊的手動設定沿用在有效範圍內，低於 1.0× 以 1.0× 顯示。效能調節不會改像素比。
   - 任何新場景與新特效必須做**電腦／手機分檔（`TOUCH` 與畫質低中高）**：手機版地形格距加大（三角形減半）、省略 `fd` 細小裝飾、關閉 `tagSurfaces` 與 `surfaceDetail`、減少樹木／岩塊／藤蔓實例數、小河動態頂點色隔幀更新、貴的光影特效只開在電腦版。
   - 手機預設幀率上限為 60 FPS，以瀏覽器畫面回呼的穩定頻率開放 30、45、60、90、120 FPS。實際上限不超過已驗證的檔位，手動設定會保存。一旦驗證本頁支援某檔，當頁遇到暫時降速時仍保留該選項。走路、船舶與釣魚獨立排程至 60 Hz。進房前主場景 20 FPS，離開填名字時停止角色預覽。分頁藏起來就暫停主迴圈。
   - 手機動態畫質預設關閉。連續 4 秒偏離幀率目標才觸發提示或降一檔，穩定約 16 秒才恢復一檔。設定存在 stormcast.adaptiveGfx，選保持關閉後不再提示。特效減量只在執行時套用，像素比、幀率上限與儲存的畫質保持由玩家控制。
   - 手機重畫陰影的上限是大廳 10 Hz、局內低畫質 15 Hz、中高畫質 30 Hz。水花只更新和上傳仍存活的實例。
9. **岸邊的浪跟著風向（`renderShaders.js` 的 `shoreFace`、`shoreTilt`，參數 `SHORE_WIND`）**：
   - 岸浪大小乘上「這段岸面迎不迎風」（離岸距離圖的梯度＝往海那一面，跟風吹來的方向比），背風面只剩 `lee` 成；相位加上順風斜推項，參考點跟著鏡頭走、`uShoreP` 累積補償，浪才不會跳。新增任何用 `shorePhase`／`shoreExpo` 的地方都要一起乘上、加上。
   - 地形著色器不准讀 `uShore`（會超過手機 16 個貼圖單元），迎風判斷改用地形自己的法線 `vN.xz`。
10. **部署同步提醒**：
   - 只改純前端畫面檔推發佈分支即可；一旦改到 `server/` 或 **3-A 列出的雙端共用檔**，上線時必須同步更新雲端伺服器（重啟服務會踢除房內連線），動伺服器或推 `main` 前務必先由使用者指示。
10. **介面顏色不寫死**：DOM 介面一律用 `index.html` `:root` 的 CSS 變數（JS 改顏色也寫 `'var(--sea)'`）；SVG／Canvas 畫的介面（表情輪盤、名牌、地圖標籤）照同一組色值。手機提示裡的按鈕名稱用 `touchSet()` 換成圖示，「互動」畫的是按鈕當下的圖示，所以 `updatePrompt` 要先 `touch.update` 再設提示。
10. **碰撞形狀與角色寬度**：
   - 母島岩石高度圖的原點與格距要對齊，形狀本身不額外膨脹；角色寬度由移動探測處理。水下查詢不能把棧板上的物件當成水下的牆，高速移動須分段檢查路徑。
   - 大港小屋石砌地基與門前平台的範圍、高度跟隨模型及實際地形，燈塔與燈標的底座、塔身分開計算。
11. **人物下落與河水**：離地或跳起時保留當下水平移動及河水速度；空中只能逐漸調整方向，撞牆消除受阻分量，落地清除空中速度。河水只推動接觸河床的人，離開瀑布後由慣性接手，避免重複施力或離開判定範圍時突然停住。
12. **船與棧橋的上下層**：人從船跳到橋時，依腳的高度選橋面或橋底；船和橋重疊時，腳高於橋面就選橋面。空中更換支撐面須維持原本的世界高度。船與棧橋間跨步的額外補位不能算進離地速度，否則人物會被彈飛。
13. **船上碰撞**：甲板範圍與船殼模型共用分段和寬度，艙蓋提供可踩的頂面。船舷按模型高度阻擋走路；足夠高的跳躍及走向附近碼頭仍可離船。
14. **天上的雲全部是手繪平塗風（`clouds.js` 烘焙、`renderShaders.js` 的 `paintTap`／`paintShade`／低雲層、參數 `CLOUDS`）**：
   - 晴天的積雲：載入時烘一張立方體環景圖（RGB 表面方向、A 有沒有雲），雲是一堆球疊成的，雲底大致是平的、高度微微起伏；會飄到頭頂的雲（`deep`）底下是幾顆大球圍成一團。天色一沉積雲轉成風暴灰。
   - 變天時的雲是著色器直接畫的**一整片低雲層**（高 `stormH`）：天色越沉從零星幾條長成整片，平塗三階、順著風拉長，暴風時底下再飄碎雲。它不用貼圖，所以天空、電腦海面倒影、手機倒影都一樣；沒有積雲圖的材質（手機倒影、`?nopaint`）晴天也留幾條，並保留三階平塗的地平線積雨雲。**不要再用一顆顆球去堆頭頂的風暴雲**（從底下看是一坨一坨的）。
   - 雲固定在世界座標、順風飄：積雲當成高 `H` 公里的平面做位移，`uPaintOff`＝鏡頭位置－飄移量；越靠近地平線的雲（仰角在 `nearLo`～`nearHi` 以下）越不跟著移，才不會把遠方的大積雨雲拉歪。A、B 兩組位移，A 飄出 `loop/2` 就由 B 從上風處接手，交疊 `morph` 公里，天空一塊一塊輪流換過去。低雲層用 `uDeck` 一路累加、不用換組。
   - 雲影：`main.js` 的 `driftClouds` 每幀從佈局（`cloudCores`）算出每朵積雲投在地上的位置，取最近 `shadowN` 朵傳 `uCloudSh`，與天上畫出來的對得上；變天時整體再照 `uGloom` 變暗。低面模型（母島、港口）原本就沒有雲影。改佈局、平面高度或位移公式時，`paintDir` 與 `driftClouds` 要一起改。
15. **魚大家共用（`server/room.js` 的 `loose`，參數 `SHARE`）**：
   - 自己的魚放在地上、甲板上、籃子裡（`fish.js` 的 `_pub` → `put`），伺服器記進 `room.loose`，同房的人都看得到；拿回手上、放進自己魚箱就 `take` 收回。誰先 `grab` 到算誰的（伺服器把那條從原主人的 `p.fish` 搬到撿的人名下）。魚箱裡的、手上的不在 `loose`，別人拿不到。
   - 母島籃子是共用的：按鈕送 `sell`（不帶清單），伺服器把籃子裡全部賣掉、每條的錢付給牠現在的主人。紀錄：價值 ≥ `SHARE.credit` 算釣到的人（`f.by`），其他算賣的人。
   - 地上、籃子裡放超過 `SHARE.life` 秒就消失（甲板上的不算）；主人斷線太久被收走時，他的魚留著變成沒主人。放在外面的魚不存進存檔、不在斷線接回的 `resume.fish` 裡，接回時照 `snapshot.loose` 放回原位；合併房間時一起搬過去。
   - 短斷線接回時，依伺服器的手持漁獲及場上物件清單補回漏收的漁獲、移除已交付或賣出的魚。船沉或被收走時清除該船的散魚，魚箱仍按漂浮規則處理。
   - 別人的魚只在本機畫（`remote`），不跳不滑；位置以主人那邊為準，他那邊跳一下、換地方會再送一次 `put`。
16. **魚箱與送東西（`server/fishBoxes.js`，參數 `FISHBOX`，算式 `src/boxdata.js`）**：
   - 箱子是伺服器的物件 `room.boxes`（`{bid, owner, fish:[uid], k, x, y, z, yaw, b}`；`k`＝`hand` 抱著／`d` 甲板（`b` 是哪個人的船、座標是船的局部座標）／`g` 地上／`w` 海上），改了就廣播 `{t:'box', add/del}`。箱裡的魚還在主人的 `p.fish`，但不在 `loose`、不存進頂層存檔，別人拿不到。
   - 只有一種箱子，每人最多 `FISHBOX.max` 個；滿了再買，伺服器回 `boxFull`，玩家答應後帶 `replace:true` 再買，最舊的那個連魚一起清掉。買了直接抱在手上；只有主人抱得動，抱著走路照箱裡重量變慢（`player.load`），不能游泳、爬梯（下水就自動放在海上浮著）。
   - 放魚不限條數、照模型體積：`boxFit` 看太長（`BOX_LONGEST`）或滿了。魚放進別人的箱子＝送給箱主（`boxIn`）。抱著箱子對準籃子／大港吊鉤按 E 整箱賣（`sell` 帶 `bid`），箱子留在手上。
   - 送魚、送箱（`give` → 對方收到 `offer` 跳卡片 → `giveAns`）：`FISHBOX.offerSec` 秒沒回答算拒絕；送箱連裡面的魚一起，對方已經有 2 個箱子就送不了。
   - 存檔：箱子跟著主人存（`savedBoxesOf`／`loadBoxes`），斷線太久收起來、下次進來 `homeBoxes` 放回自己船的甲板上；舊存檔的 `boxLv` 換成一個箱子。船沉了甲板上的箱子浮起來（`floatBoxes`），魚還在。
17. **平板（`src/tablet.js`、`tabletApps.js`，參數 `TABLET`）**：
   - 畫面上只留錢、時間天氣小圖示、互動提示、張力條、體力、船上的耐久燃油；房間、風向、餌、地圖都搬進平板。拿著平板時遊戲按鍵不動（`tabOpen()`）、角色站著不動、船放開油門；空手走路時雙手捧著平板（`h` 訊息送 `'tablet'`、`len` 是螢幕上第幾個畫面，別人看得到他在看什麼）。拿起／收起有動畫：3D 平板跟著手臂抬起放下（`player.js` 剛捧東西時手臂慢一點；平板推在手心前面，手在背後）。
   - 看手上的平板（`main.js` 的 `tabletCam`、`placeTabletDom`）：拿在手上時沒有大螢幕；鏡頭（第一、第三人稱、手機都一樣）花 `TABLET.viewSec` 秒沿平板正面退到剛好框住它（佔畫面 `TABLET.fill`／`fillTouch`），自己的身體只留手臂、靠近鏡頭那段用裁切面切掉；平板介面（`#tab.held`，排版寬 `TABLET.domW`／`domWTouch`）每幀照 3D 平板四個角的投影算 `matrix3d` 貼上去，照樣點得到。拿不到手上時（抱魚、掌舵、游泳、坐著）才是原本置中的大螢幕（從下方抬上來，`--lift`＝`TABLET.lift`）。
   - 設定：進房後（`body.playing`）左上角的設定鈕收起來，整塊 `#panel` 由「設定」app 搬進平板（`tabEnv.settings`），離開 app 再搬回原位；大廳時照舊在左上角。音效預設開（第一次點擊／按鍵才開得了；`?test` 分頁不自動開），音量滑桿 `stormcast.vol`。
   - 叫船 `{t:'call'}`、換船 `{t:'swap', type}`（`server/boatCall.js`）：人要在潮汐灣港口 `TABLET.harborR` 以內、船上沒人（看每個人位置的第 9 格「站在誰的船上」）；船停到離人最近的空船位（`reberthNear`）。叫船伺服器回 `called`，船主那邊把船放過去再照常回報位置；別人那邊差太遠會直接跳過去。叫船有 `TABLET.callCd` 秒冷卻。
   - 換船前須搬離甲板上的散魚和魚箱，包含其他玩家放上去的物品。
   - 船主離線後，船與泊位保留 `SERVER.reconnectSec`（預設 3 分鐘）。回收時仍在船上的乘客回潮汐灣木平台，手持漁獲和魚箱跟著人，自有甲板魚箱搬到碼頭。乘客斷線時也記住回港位置。
   - 圖鑑：伺服器在 `bait()` 記下釣點的地名（`placeOfSpot`），`land` 時 `recordDex` 更新 `p.dex`，`caught` 帶 `dex` 那一筆；`snapshot` 帶整本 `dex` 和倉庫船況 `stored`。圖鑑不放進家當存檔：`hub.keep` 另外寫進 `dexbook.json`（`Dexbooks`，不分期），進房時 `loadDex` 讀回來，全服刷新不清。
   - 畫面上指向自己的船：離船超過 `TABLET.markFar`（而且不在船上、沒拿平板）時，看得到就標在船上方、看不到就貼畫面邊（`markMyBoat`，樣式跟魚箱標記同一套）。叫船、換船後不管多近都標 `TABLET.markSec` 秒（珊瑚色、會跳，`flashMyBoat`）；給玩家看的訊息不講第幾號船位。

18. **據點、船務、漁會與船隊的規則（2026-11-17 改版）**：
   - **修船**：扳手和「加固船殼」改裝都沒有了。船壞了只能在修船屋／大港船塢的修船台付錢修滿（`repairBoat`，帶 `forId` 是幫同隊隊友付）；破洞每個讓極速掉 `CRACK_SLOW.each`、最慢剩 `floor`。
   - **工位不是商品**：商品架上的 `repair`、`title`（捐款箱）、`mailbox`、`altar`、`paint` 各有自己的互動（`main.js` 的 `openStation`／`repairAt`），伺服器的 `buy` 不收它們（塗裝是 `paint:<id>`，要站在塗裝櫃前才能買，買過的隨時換）。
   - **船的狀態 `s[9]`**：1 船燈、2 有人掌舵、4 擱淺、8 集魚燈、16 綁著岸上的纜繩（伺服器只收 0–31）。`boatInfo` 另外帶 `lv`（引擎）、`mods`、`paint`，改了要廣播 `boat`。
   - **船對船碰撞**（`collideBoats`）：每個人只推自己算的那艘，讓多少照噸位分（`對方 ÷ 兩艘合計`）；對方綁著纜繩（`tied`）或船主離線（`reclaimAt`）就自己全讓。只有推擠、反彈、扭開、橫搖（`BOATHIT`），**不扣耐久**。
   - **拖船**：伺服器只記誰拖誰（`room.tows`，一艘只能參與一組，要對方按同意）。拉船的物理在「被拖那艘是誰在算」的那一邊算（`updateTows`：拖纜拉直後 `pushBoatSafe`、船頭轉向拖船船尾），拖船那邊只把極速乘 `TOW.speed`。離太遠、沉船、離線由伺服器斷。
   - **副駕**：同隊的人站在隊友船上、船主沒掌舵時可以開。那艘船改由副駕的瀏覽器算（`boat.local = true`，`others.js` 就不再補位），位置用 `{ t: 'b', forId }` 送、沉了用 `{ t: 'sink', forId }`；船主那邊 `piloted` 期間自己的船照 `k` 傳來的擺（`updateRemote`），耐久照 `s[11]` 扣。漩渦旋臂、巨浪捲舌這些額外傷害副駕那邊不算（只算一般風浪）。船主握方向盤就收回。伺服器的規矩（`party.js` 的 `helm`、`room.js` 的 `enter`）：船主要在線上、一個人一次只開一艘（接新的那艘，舊的自動交回）、副駕回報沉船時人要真的在那艘船上；退隊、斷線、被併房（`enter` 非 resume）一律把 `boat.pilot` 清掉。
   - **誘魚桶**：身上幾桶是伺服器記的（`kit.chum`），手上、甲板上的桶子只是照數字擺（`syncChums`，少了補在自己船的船尾右側）。丟進海裡時 `fish.js` 的 `landed` 送 `useChum`；伺服器不收的話桶子回到船上。
   - **漁會**：捐款要站在捐款箱前（伺服器量 5 公尺）；每週一 `GUILD.hour` 點換週，榜和稱號一起清（`server/index.js` 每 100 拍看一次）。稱號是照榜即時算的（`titlesFor`），不是買的；改了用 `title` 廣播，別人的名牌重畫。
   - **夜間照明**：整個場景只有 4 盞點光源，鏡頭靠近修船屋或大港時借過去用（`main.js` 的 `lampSlots`）。窗戶的亮面（`glowQuads`）和海面光圈一律不寫 alpha（畫面的 alpha 是「是不是天空」的記號）：用不透明材質，或只加亮的混色。

## 5. 文件動態維護協定（AI 必執行）

為了防止工程文件腐化過時，任何 AI 在完成程式碼修改準備收尾時，請逐項核對以下清單；**只要命中任一項，請在同一個任務內直接更新本文件（與相關規則檔）**：

1. **新增、刪除或合併檔案／模組** → 更新〈3. 目錄與模組地圖〉，特別標明是否屬於「雙端共用（禁碰 Three.js / DOM）」。
2. **修改世界配置、新增島嶼／港口／釣場或改動座標架構** → 同步更新本檔〈1. 專案定位與世界現況〉與 `docs/座標與地圖規則.md`。
3. **新增或修改網址測試參數、啟動指令、開發者快捷鍵** → 更新〈2. 開發、預覽與實測速查〉。
4. **踩到新的跨平台／效能／渲染／物理大坑並修好** → 濃縮成 2～3 行規則補進〈4. 核心工程鐵律與踩坑紀錄〉。

### 維護撰寫原則
- **只寫「現在程式碼長怎樣」，不寫歷史流水帳**：舊設定被取代就直接改寫或刪掉，不要留「以前是 X、某月某日改成 Y」（歷史交給 `git log`）。
- **保持精煉可掃讀**：優先使用表格與條列，整份手冊控制在 250 行以內，確保後續 AI 一次 `Read` 就能完整讀入且不浪費上下文空間。
