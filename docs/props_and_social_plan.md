| **玩家意見收集系統 (`feedback`)** | **僅設「港口 3D 實體『漁會意見信箱（郵筒）』」入口（不設平板按鈕、不附帶環境診斷快照）**：於母港魚市場（及大港榮譽榜亭旁）設立 3D 郵筒，玩家走近按 `E` 彈出輕量意見回報小卡（分類 3 選 1：`🐛 Bug 回報`／`💡 玩法建議`／`📱 卡頓／操作問題` ＋ 最多 `200 字` 內容）。送出 `{ t: 'feedback', kind, text }` 後存入 `DATA_DIR/activity/feedback.jsonl`（僅存時間、分類、玩家 `name`／`pid` 與意見內容，含 60 秒防洗版冷卻），並直接整合顯示於 `/admin/stats`（`server/statsPage.js`）管理網頁。 |

## 三、 重要單元測試相容性規範（實作前必讀！）

1. **`tools/security.test.js` 相容性（`mods.hull`、`scr <= 8` 與 `TITLE_NAMES`）**：
   - 第 146 行檢查 `assert.deepEqual(p.tab.mods, { sonar: true, hull: false, lamp: false });`，因此即使從 `BOAT_MODS` 刪除 `hull`，在 `server/room.js` 的 `cleanTabState()` 內**必須保留** `for (const k of ['sonar', 'hull', 'lamp']) mods[k] = !!rawMods[k];`。
   - 第 136 行檢查 `assert.equal(p.tab.scr, 8);`，因此平板維持現有 7 個桌面 App（不新增第 8 個「榜單」App 圖示，將漁會捐款與稱號整合於既有「背包」與「房間」App 內）。
   - 第 149 行檢查 `assert.deepEqual(p.tab.titles, ['討海人']);`，因此在 `src/boatdata.js` 保留匯出 `HONOR_TITLES`，並在 `server/room.js` 的 `TITLE_NAMES` 白名單中同時納入新稱號與舊稱號 `'討海人'` 以確保測試通過。
2. **`tools/gameplay.test.js` 相容性（`HAVEN_PUMP_W` 與 120m 漩渦吸力）**：
   - 第 150 行測試大港加油柱 `HAVEN_PUMP_W` 與 `t: 'pump'`：移除大港場景中的 3D 加油柱模型與前端互動提示（玩家在遊戲中統一使用手提油桶加油），但在 `src/layout.js` **保留匯出 `HAVEN_PUMP_W` 座標常數**、在 `server/room.js` **保留 `case 'pump'` 後端處理**，讓既有單元測試無縫通過。

- **在海上修船屋／大港船塢「買新船 (`fisher`/`trawler`)」原地換船與邊界防護**：
  - 當玩家在海上修船屋或大港灣島船塢購買新船時：
    1. **舊船狀態入庫**：先將目前船隻的油量與破洞存入 `p.stored[kit.active] = { fuel: p.boat.s[10], cracks: p.boat.cracks }`（保留舊船與其原本的引擎等級），新船初始為 `engineLv: 0`。
    2. **重配相容泊位格**：呼叫 `reberthNear(this, p, newType)` 為新船重配符合尺寸的港口泊位（防止從 `skiff` 小船格升上 `trawler` 大船後，斷線重連回港時大船卡進小船棧橋）。
    3. **解開舊繩索並重排甲板物品**：自動解開岸上繫纜 (`moor = -1`) 與拖船配對 (`towCut`)，將船體原地切換為新船（保留船塢停靠座標與朝向），並將甲板上的魚箱與散魚自動重排至新船**前甲板安全區 `x: +1.2 ~ +2.5`**（避免卡進中後段的封閉駕駛艙 `cabin`），跳出提示告知「新船已停妥於船塢旁（新船引擎為 Lv.0，可於船屋內個別升級）」。
